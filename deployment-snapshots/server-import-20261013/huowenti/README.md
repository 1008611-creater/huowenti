# 活问题 / Living Question

知乎黑客松 2026 参赛作品。当一个问题公开内容答不清楚、但经历过这件事的人真实存在时，**活问题**把这个问题拆开、标出读不到的部分，然后主动去找那些经历过的人，把他们的经历变成可以互相比较、逐条核对的记录。

> 有些答案不在互联网上，它们还在经历过这件事的人手里。

公网 Demo（固定地址）：**https://zaichang.cauai.fun**

## 快速体验

打开 https://zaichang.cauai.fun ，首页就是母问题「2027 届普通本科生找第一段 AI 产品实习到底有多难？」。

依次可以体验：**活问题现场 → 三个缺口 → 参与采访 → 追问 → 贡献确认 → 问题变化 → 当前调查结论 → 知乎回答 → 知识宇宙 → 提出新问题**。

想以参与者身份走一遍：点「回答一个只有你知道的问题」，选一个最接近自己的位置（四类身份），回答 5 至 6 个问题，系统会针对你填的内容追问一句，然后生成一张贡献卡。**确认后这份经历才会进入调查。**

## 产品闭环

```text
活问题现场   一个问题，先展示它现在能回答到什么程度
三个缺口     把「读不到的部分」逐条标出来，作为去找人的理由
参与采访     按位置选身份，问题只问那一部分
追问         针对刚填的内容，追一个只有当事人能回答的问题
贡献确认     生成贡献卡，用户确认后才进入调查
问题变化     这份经历让哪一条子命题的覆盖状态变了
当前结论     六条子命题各自的证据状态、相反经历与仍未解决
知乎回答     整理成一份可编辑、可复制的回答草稿
```

## 六条子命题（固定拆法）

```text
初始背景    学校背景、专业、已有实习和已有项目
项目经历    项目是否可运行、是否有真实用户、个人贡献是什么
投递过程    投递渠道、投递数量、目标公司类型
面试筛选    简历反馈、面试阶段、具体淘汰位置
公司差异    大厂、成熟公司和 AI 创业公司的判断差异
最终结果与失败过程  最好进度、Offer 情况、做过但没有产生效果的准备
```

固定拆法的意义是：**不同人填的经历可以横向比较**，而不是一堆无法对话的独立故事。

## 四类参与身份

| 身份 | 会被问到 | 对调查的作用 |
| --- | --- | --- |
| 我已经拿到实习或进入面试 | 6 个问题 | 补充一条成功路径，并生成寻找条件相近失败者的对照任务 |
| 我投递过，但没有结果 | 6 个问题 | 补充一条失败过程，推动区分学历、公司类型、项目可验证性与简历表达 |
| 我正在找第一段 AI 产品实习 | 5 个问题 | 增加需求信号，决定下一步优先调查什么 |
| 我参与过招聘或面试 | 5 个问题 | 补充招聘方视角，验证或推翻求职者对淘汰原因的猜测 |

## 证据模型

可信度不是一个黑盒分数，而是四种可解释、可复核的状态，**按六条子命题分别计算**：

| 状态 | 含义 |
| --- | --- |
| `multi-case` 已有多份经历 | 已有多份个人经历，可以开始比较条件差异 |
| `single-case` 只有一份经历 | 只有一份个人经历，还不能说明普遍情况 |
| `public-only` 只有公开讨论 | 只有公开讨论，缺少当事人提供的完整过程 |
| `empty` 覆盖不足 | 当前检索范围内覆盖不足 |

**相关性判据只有一套**：同一套关键词同时用于「地图上挂哪些内容」和「提出新问题时判断这个领域够不够」。只有当内容**直接指向母问题**（在校生找第一段实习：实习 / 求职 / 面试 / 简历 / 校招 / 应届 / 招聘 / 投递 / offer / 本科 / 毕业生 / 就业 / 产品经理…）才算相关。泛职场内容（职场 / 职业 / 工作 / 升职 / 加薪 / 职业倦怠 / 职业发展）一律排除，因为它们不回答这个问题。

**相反经历识别**：两份经历如果在「本科 / 大厂 / 创业公司 / 有真实用户」等条件上相近、结果却相反，会被自动标记为对照连线，提示继续追问，而不是取平均。

## 三维图谱

页面主体是一张 **时间 × 子命题 × 内容数量** 的三维图：

- 横轴是时间：左半段是更早的公开来源（2020–2023），右半段是当前调查区间（2024–2027），按季度划分。
- 纵轴是六条子命题。
- 高度是这一格里有多少条内容。

**每颗星都是一条可以点开核对的内容**；密度微光只表示「这一格内容多」，不可点击、不计入统计。三根轴共用同一个原点，都是直线。

**粒子是细小星光点，不是泡泡或球体**——这是硬约束。

## 数据来源与降级

- 公开内容底账使用知乎黑客松提供的免鉴权公开接口：`api.zhihu.com/km-indep-home/hackathon/v2/{story|knowledge}/list`，当前接入 30 条。
- 服务端已实现知乎开放平台搜索接口（`developer.zhihu.com/api/v1/content/zhihu_search`），配置 `ZHIHU_ACCESS_SECRET` 后可作为公开内容补充；**未配置时页面如实标注为关闭，不会伪造来源**。

**诚实边界（重要）**：这 30 条内容按母问题逐条比对过，**当前没有一条直接指向「在校生找第一段 AI 产品实习」**，因此它们全部被排除在三维图之外，图上显示「公开来源 0 条」。这不是页面故障，**正是这个产品要表达的缺口**——一个真实存在、但公开内容答不清楚的问题。产品的价值恰恰在于指出这块空白，然后去找能填上它的人。页面会把这句说明直接写在图上。

## 如何复核

仓库里带两套可直接运行的检查，都是真实请求，不是示意：

```bash
npm start                 # 启动服务（默认 4173）
npm run security          # 静态资源与响应头边界检查（60 项）
npm run e2e               # 真实浏览器端到端验收（31 项，需先装 playwright）
```

端到端验收会走完「采访 → 追问 → 贡献卡 → 问题变化 → 结论 → 回答草稿 → 新问题判定」，并对三维图做像素统计，确认图上真的画出了内容、画面真的在动、五种宽度都没有横向溢出。跑完后请把验收产生的临时贡献删掉（页面上可直接删除）。

## 安全边界

演示站点面向公众，服务端只对外提供前端必需的页面与资源，其余一律不通过 HTTP 暴露。

- **静态资源白名单**：只有首页（`/` 与 `/index.html`）、`huowenti.css` / `huowenti.js`、`/assets/` 下的字体与图标、`robots.txt` 可访问。
- **后端内容一律 404**：源码、`data/`、`lib/`、`scripts/`、`logs/`、`docs/`、依赖目录、`.git`、`.env` 与各类配置文件都不对外提供。
- **目录穿越已拦截**：请求路径先做 URL 解码与 `.` / `..` 折叠，任何包含 `..` 的路径直接返回 404，编码形式（`%2e%2e`、`%2f`）同样拦下。
- **响应头收紧**：`Content-Security-Policy`（脚本只允许本站、禁止内联脚本与 `eval`）、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`（关闭定位、摄像头、麦克风、支付）、`COOP` / `CORP`，并关闭 `X-Powered-By`。
- **默认可嵌入性关闭**：`X-Frame-Options: DENY` 与 `frame-ancestors 'none'`。
- **只提供一个 API 命名空间**：对外接口只有 `/api/health` 与 `/api/huowenti/*`；开发过程中出现过的旧接口（`/api/cases`、`/api/corpus`、`/api/weather`、`/api/analyze`、`/verify/*`、`/case/*`、`/oauth/*`）已全部下线，实测返回 404。
- **密钥边界**：知乎凭证只从服务端环境变量读取，不进前端、不进 URL、不进日志、不进截图、不进仓库。

## 隐私边界

- 不自动读取 GPS，不要求精确位置
- 不要求实名，参与者可以选择匿名
- 不把单条个人经历当作普遍事实
- 不收集与问题无关的个人信息
- 贡献可以随时删除
