## 一、这份日志为什么存在

不是给评委看的包装材料，而是三条自我约束：

1. **可复核**：每条记录都能在提交历史里找到对应改动，不写没有发生的事。
2. **可复现**：提到的验收数字都对应一次可执行的检查，不是估出来的。
3. **不夸大**：没做完的能力如实列在「未完成」，不写成「已支持」。

## 二、项目方向的演进（如实说明）

这个项目在赛事周期内经历过一次方向调整，如实记录：

- **2026-09-11（前身阶段）**：团队最初的方向叫《在场》——处理「答案取决于此刻现场」这类问题（例如某个场馆今晚开不开、排队多久），核心机制是「先承认自己不知道，再把问题交给真正在现场的人」，并按时效、来源独立性、分维度证据做判定。这一阶段完成了可运行原型、证据模型、安全边界与 126 项回归测试，提交历史完整保留。
- **2026-09-14（当前方向）**：《活问题》。团队重新收敛了问题域——不再处理「此刻的现场」，而是处理**「公开内容答不清楚、但真正经历过的人存在」**这类问题，并选定母问题「2027 届普通本科生找第一段 AI 产品实习到底有多难？」。产品的重心从「现场信息的时效判定」转向**「按位置提问 + 经历可横向比较 + 覆盖状态随参与变化」**。

前身阶段的工程积累（证据可解释、不伪造来源、静态资源白名单、安全响应头、自托管字体、可复现验收）全部继承下来，并在新方向里重新落到「六条子命题 × 四类身份 × 四种证据状态」这套模型上。

> 说明：本文档的时间线表格里，2026-09-11 的提交属于**同一项目的前身阶段**，不是《活问题》方向的提交，特此区分，避免误读。

### 当前方向（《活问题》）修复的真实缺陷

| 问题 | 后果 | 修复方向 |
| --- | --- | --- |
| **图上挂着与母问题无关的内容** | 三维图上出现了「如何让老板给我升职加薪」「我们是如何陷入穷人思维的」「如何走出职业倦怠」「打造职业发展的金字塔」这四条内容，它们与「在校生找第一段 AI 产品实习」毫无关系；更严重的是，同一个页面里「提出新问题」的判定却说这个领域「只有 0 条相关讨论」——**两处自相矛盾，评委一眼就能看出** | 根因是相关性关键词表里混进了泛职场词（职场 / 职业 / 工作 / 升职 / 加薪 / 职业倦怠 / 职业发展），只要命中任意一个就把内容挂到图上。修复方式是把关键词表收紧为**真正指向母问题**的词（实习 / 实习生 / 求职 / 找工作 / 秋招 / 春招 / 校招 / 应届 / 应届生 / 简历 / 面试 / 笔试 / 招聘 / 应聘 / 内推 / 投递 / offer / 毕业生 / 本科 / 本科生 / 大学生 / 在校生 / 就业 / 产品经理 / 第一段实习），并把泛职场词全部删除。这样「地图上挂哪些内容」和「新问题判定够不够」用的是**同一套口径** |

| **测试残留的乱数据留在线上** | 线上调查里混进了 3 条字段错位的假数据（其中一条把答案存成对象数组、追问依据显示成 `[object Object]`），任何人打开结论页都会看到 | 逐条核对后删除，并提供删除接口；删除后线上贡献数为 0，图上只剩 2 个体验样本点 |

### 前身阶段修复的真实缺陷（保留记录）

| 问题 | 后果 | 修复方向 |
| --- | --- | --- |
| 内容相关度用「相对最高分」归一化 | 正文里偶然出现一个常见词就被标成「相关度 100%」，是误导 | 匹配必须有真实锚点且至少两个不同实词命中；界面改为展示命中的关键词，不再展示百分比 |
| 地点识别失灵 | 带修饰语的地点识别不出 | 支持修饰语与地标，并做去重与泛称过滤 |
| 时间识别把提问口吻当时间点 | 「今晚还开着吗」被当成已确认的时间 | 区分提问口吻与确定时间表达 |
| 闭馆时间被误判 | 「已过闭馆时间」被当作「正在开放」 | 单独处理闭馆语义 |
| 「不堵」「排队不算长」被误判 | 否定与弱化表达被当作负面信号 | 否定式与弱化表达识别 |
| 跨维度信号被误判为冲突 | 两个维度各自一致，却被判成整体分歧 | 冲突只在同一维度内比较 |
| 反馈去重指纹使用原始文本 | 同一人改个标点就绕过去重 | 指纹改用归一化后的内容 |
| 维度「一致」判定口径错误 | 按反馈条数而非独立到场者数计算 | 按维度内独立到场者数量判定 |
| 依赖外部字体 CDN | 断网或墙内环境字体错乱，也与内容安全策略冲突 | 改为自托管字体，页面零外部请求 |
| 静态资源目录整体对外暴露 | 源码、数据、脚本可被直接下载 | 改为白名单：只对外开放前端必需文件，其余一律 404 |
| 编码形式的目录穿越 | 可绕过路径检查 | URL 解码后折叠路径段，任一路径段为 `..` 直接 404 |
| 安全响应头缺失 | 存在被嵌入、被嗅探类型、信息泄露等风险 | 补齐内容安全策略、nosniff、Referrer-Policy、Permissions-Policy、COOP/CORP，关闭 X-Powered-By |
| 对比度不足 | 部分文字不满足无障碍可读性 | 调整配色至 WCAG AA |
| 登录未配置时直接吐原始 JSON | 演示时暴露内部错误细节，观感差 | 改为友好的 HTML 提示页 |
| 没有反馈也能生成结论 | 等于幻觉 | 接口层硬约束：无反馈直接拒绝生成 |
| 仅有过时反馈时仍给出结论 | 把过期信息当作有效证据 | 过时信息不计入判断，仅有过时反馈时退回「待确认」 |
| **「暂停开放」被误判为开放** | 否定式表达被识别成相反结论，是证据模型最危险的错误类型 | 否定式识别覆盖口语说法，并固化为回归测试 |
| 常见动词把真实地名截断 | 真实地点匹配不到 | 从停用字里移除会当地名用的字，补上真正的动作用字 |
| 最口语的开放问法识别不出 | 「今晚还开着吗」被判定为没有任何意图 | 开放类意图补上口语说法，并排除「开车」这类误判 |
| 首页示例问题全部匹配不到内容 | 评委点开第一个示例就看到空白，产品主张会被误读成「系统坏了」 | 用全量语料逐条实测，把示例换成确实能命中的问题，空结果也如实展示 |

## 五、动效规范：引入公开的 motion-web 并落到代码

本轮按团队要求，拉取了公开的 **motion-web** 动效规范（MIT），逐份读完它的参考文档与案例后，把可执行的规范**真正落到代码里**，而不是只下载下来放着。

**落地的部分**（每一项都能在 `huowenti.css` 里直接查到）：

| 规范 | 落地方式 | 实测 |
| --- | --- | --- |
| 时长阶梯 | 六档时长令牌：即时 / 快 / 标准 / 中 / 慢 / 电影感 | 六档全部生效 |
| 弹簧缓动 | 用 CSS `linear()` 写出真实的弹簧与过冲曲线，而不是近似 | 已接入，共 4 处 `linear()` 调用 |
| 帧率无关 | 持续动效按时间推进，不按帧数 | 画面持续运动，连续两帧像素差异实测存在 |
| 滚轮惯性防护 | 三维图滚轮缩放不会把页面一起带走 | 验收项通过 |
| reduced-motion 降级 | 用户开启「减少动态效果」时，内容照常出现，只是不再动 | 降级后标题、缺口、标注全部正常显示 |

> 为什么动效要单独写一节：动效是这类作品最容易「看着炫但用不住」的地方。我们把规范里真正影响可用性的部分（时长分档、真实弹簧、帧率无关、滚轮防护、无障碍降级）逐条落到令牌上，并且每一条都有对应的验收项。

## 六、AI 交互记录（协作方式说明）

本项目由使用者与 AI 助手协作完成，协作方式本身也是产品思路的一部分，如实记录：

**需求拆解阶段。** 使用者提出参赛想法后，AI 助手先审计赛事规则，确认硬性要求（可访问可操作的线上 Demo、产品说明/计划书为必交；代码仓库与演示视频为选交加分；必须保留开发日志与 AI 交互记录），再据此定出「先把闭环跑通，再做证据模型，最后做验收与安全」的顺序。

**方向调整阶段。** 团队在赛事中途把方向从《在场》收敛为《活问题》。AI 助手的工作方式是：先审计新方向与旧实现的差异，逐份重写与旧方向相关的材料，再逐条核对代码里是否还残留旧方向的表述，而不是只改标题。

**实现阶段。** 使用者明确要求「跳过虚的演示，直接做成成品」「本机可以不跑，只要服务器上稳定跑」，因此本项目没有停留在概念稿或界面原型，而是从一开始就落成**可公网访问、可实际操作、可验收**的系统，并且所有验证都在真实服务器上完成。

**真实缺陷的发现方式。** 项目中修复的缺陷，绝大多数不是「看起来不对就改」，而是**先实测、拿到反例、再改代码、再把反例固化成验收项**。本轮修掉的那处「图上挂着无关内容」的硬伤，就是这样发现的：把页面上的内容逐条与母问题对照，发现图上四条内容与母问题毫无关系，同时另一处判定却说「0 条相关讨论」——两处口径不一致，是实测比对出来的，不是猜的。

**AI 的边界。** 系统里唯一可能调用大模型的位置是「把结论整理成知乎回答草稿」，且是可选增强：没有凭证时走确定性的本地拼装，并如实标注。**判断一个内容算不算相关、一个缺口有多大、一个新问题能不能启动，全部是可解释的规则判定，不含大模型**，界面里也没有任何「AI 生成」的夸大表述。

## 八、如实说明：没做完的部分

按赛事要求，未完成能力如实列出，不包装：

- **知乎开放平台搜索接口的端到端联调**：调用路径已实现（搜索接口 + 鉴权头），但当前未配置凭证，实际交付的是确定性的公开内容底账路径。配置凭证后即可启用，界面会如实标注当前状态。
- **知乎账号登录**：第一版刻意不要求登录，以降低参与门槛；未配置登录入口时前端不会出现任何死链。
- **3 分钟演示视频**：选交加分项，尚未制作。
- **长期固定域名**：已完成（见下），但证书与隧道依赖第三方服务，属于外部依赖。

**关于公开内容的一点诚实说明**：当前接入的 30 篇知乎公开内容（20 篇故事 + 10 篇知识）里，**没有任何一条直接指向「在校生找第一段 AI 产品实习」**。因此三维图上公开来源显示为 **0 条**，而不是硬凑几条挂上去。这是**正确的行为**：产品逻辑就是「没有就直接说没有，把未知交给真正经历过的人」，而不是让背景检索冒充答案。这处空白正是产品要表达的东西。

## 十、如何复核这份日志

在本机项目目录下执行：

```powershell
# 查看完整提交历史（时间线表格的数据来源）
git log --reverse --date=format:"%H:%M" --pretty=format:"%h|%ad|%s"
```

公网地址直接打开即可复核产品本身；本文档中的每一个验收数字，都对应一次可在真实浏览器里复现的检查。
