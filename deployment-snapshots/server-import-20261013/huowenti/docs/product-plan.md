## 〇、一页纸摘要（3 分钟速读）

**一句话**：有些答案不在互联网上，它们还在经历过这件事的人手里。**活问题**把一个问题拆开、标出公开内容答不清楚的部分，然后主动去找真正经历过的人，把他们的经历变成可以互相比较、逐条核对的记录。

**问题**：有一类问题，搜索引擎和生成式 AI 结构性地答不了，因为它缺的不是知识，而是**当事人**：

> 「2027 届普通本科生找第一段 AI 产品实习到底有多难？」

公开内容里有大量方法和建议——「简历要怎么写」「面试怎么准备」「项目要有数据」。但它们有一个共同的空洞：**不包含一个具体的人从投递到被拒或被录用的完整经过**。而且这类问题的答案散落在不同位置的人手里：经历过失败的人知道卡在哪一步，却通常不会写出来；招聘一侧知道筛选的真实顺序，却几乎不公开讲；同一个项目在不同类型公司的反馈可能完全相反，却没人把两种结果放在一起比过。

**解法**：不做「AI 替你回答一切」，而是做一条**主动找人的链路**——系统负责把问题拆清楚、把已知和未知分开、把读不到的部分显式标出来；答案由真正经历过的人提供，每一条都带身份、时间和可核对的事实，并且会随着新经历进入而更新。

**凭什么成立**：

- **缺口是真的、可验证的**：当前 30 条公开内容按母问题逐条比对后，没有一条直接相关。页面把这件事直接写在图上——**空图本身就是结论**，也是去找人的理由。
- **按位置提问**：四类身份（拿到实习 / 投递没结果 / 正在找 / 参与过招聘），只问每个人知道的那一部分。招聘一侧不会被问「你投了多少份」。
- **证据可解释**：四种状态（多份经历 / 只有一份 / 只有公开讨论 / 覆盖不足），按六条子命题分别计算，不用黑盒分数。
- **可复现**：31 项浏览器端到端验收在真实浏览器与真实服务器上实跑通过（0 失败、控制台无报错、无失败请求），任何人可复现。
- **真实可用**：公网 Demo 已部署在固定域名，容器开机自启、异常自动重启，全流程走通。

**已完成**：可运行的产品闭环、八个视图、31 项验收、公网 Demo、公开代码仓库、完整文档。
**未完成**：知乎开放平台凭证的端到端联调、演示视频——如实列出，不包装。

## 一、问题定义

### 1.1 被忽略的一类问题

搜索与生成式 AI 擅长整理「已经发生并被记录下来的事」。它们有一个结构性盲区：**没有被人写下来的经历**。

| 用户的问题 | 现有产品能给的 | 用户真正需要的 |
| --- | --- | --- |
| 普通本科找第一段 AI 产品实习有多难 | 「简历要这样写」的方法帖 | 一个条件相似的人完整走了一遍，卡在哪一步 |
| 我投了 30 份没回音，是哪里出了问题 | 泛泛的优化建议 | 招聘一侧说出筛选的真实顺序 |
| 同一个项目投大厂和创业公司有区别吗 | 两种说法各自出现，从不对照 | 两种结果被放在一起比较过 |

共同点：**答案不在已经发布的内容里，而在某个具体的人的经历里，而且没有被结构化地记录下来。**

### 1.2 现有方案为什么解决不了

- **搜索引擎**：只能返回已经发布的内容，而失败过程、筛选标准这类内容，恰恰是最少被写出来的。
- **生成式 AI**：要么编一个听起来合理的答案（幻觉），要么给一段正确的废话（「多投、多练、多总结」）。
- **现有社区提问**：依赖「碰巧有相关经历的人看到」，没有按位置定向提问的机制；即使收到回答，也是一条条无法横向比较的独立故事。

### 1.3 缺的不是更多建议，而是真正经历过的人

**活问题**不试图让 AI 猜别人的经历，而是把「谁真的经历过这件事」变成一条可以主动找到人、可以交叉比较的链路。这是当前 AI 能力边界之外、但知乎社区刚好能补上的一块。

### 1.4 目标用户与典型场景

**提问者**：正在面对一个具体、有明确人群和阶段、但公开内容答不清楚的问题的人。首版聚焦一个真实且高频的场景——在校生找第一段 AI 产品实习。

**回答者**：经历过这件事的当事人，按位置分为四类。

**场景特征**：问题足够具体（能拆成可比较的条件）、公开内容明显不足（缺口可验证）、当事人分布清楚（求职者与招聘方都能被找到）。

## 二、产品解法：八步闭环

```text
① 活问题现场    一个问题，先展示它现在能回答到什么程度
② 三个缺口      把「读不到的部分」逐条标出来，作为去找人的理由
③ 参与采访      按位置选身份，问题只问那一部分
④ 追问          针对刚填的内容，追一个只有当事人能回答的问题
⑤ 贡献确认      生成一张贡献卡，用户确认后才会进入调查
⑥ 问题变化      这份经历让哪一条子命题的覆盖状态变了
⑦ 当前调查结论  六条子命题各自的证据状态、相反经历与仍未解决
⑧ 知乎回答      把当前调查整理成一份可编辑、可复制的回答草稿
```

关键设计有四处：

1. **把「读不到」显式化**：首页和三维图都直接展示当前检索范围内**没有**找到什么。缺口不是营销话术，它是这个产品要去找人的理由。
2. **按位置提问**：同一个问题，不同位置的人知道的东西不一样。选一个最接近你的位置，问题只会问你那一部分。
3. **确认后才进入**：贡献卡逐条列出用户提供的事实并标注来源，页面明确写着「这是一份个人经历，不代表行业整体情况」「不会自动发布成知乎回答」「你可以随时删除它」。
4. **结论与来源绑定**：每一格的证据状态都写清含义，出现相反经历就保留矛盾并标为对照。

## 三、证据模型（产品核心）

这是**活问题**区别于普通问答产品的部分。可信度不是黑盒分数，而是四种可解释、可复核的状态，**按六条子命题分别计算**。

### 3.1 六条子命题（固定拆法）

```text
初始背景 background  学校背景、专业、已有实习和已有项目
项目经历 project     项目是否可运行、是否有真实用户、个人贡献是什么
投递过程 apply       投递渠道、投递数量、目标公司类型
面试筛选 screen      简历反馈、面试阶段、具体淘汰位置
公司差异 company     大厂、成熟公司和 AI 创业公司的判断差异
最终结果与失败过程 result  最好进度、Offer 情况、做过但没有产生效果的准备
```

固定拆法的意义是：**不同人填的经历可以横向比较**，而不是一堆无法对话的独立故事。

### 3.2 四种证据状态

| 状态 | 触发条件 | 含义 |
| --- | --- | --- |
| `multi-case` 已有多份经历 | 当事人经历 ≥ 2 份 | 可以开始比较条件差异 |
| `single-case` 只有一份经历 | 当事人经历 = 1 份 | 还不能说明普遍情况 |
| `public-only` 只有公开讨论 | 无当事人经历，但有相关公开内容 | 缺少当事人提供的完整过程 |
| `empty` 覆盖不足 | 两者都没有 | 当前检索范围内覆盖不足 |

判定顺序体现产品立场：**当事人的完整过程比公开讨论更有价值，但只有一份时仍然不能说普遍。**

### 3.3 相关性判据只有一套

同一个关键词表同时用于两处：三维图上挂哪些公开内容（`classifySource`）、提出新问题时判断这个领域够不够（`currentCorpusHits`）。

只有当内容**直接指向母问题**才算相关：实习 / 求职 / 面试 / 简历 / 校招 / 应届 / 招聘 / 投递 / offer / 本科 / 毕业生 / 就业 / 产品经理 / 第一段实习 等。

**泛职场词一律排除**（职场 / 职业 / 工作 / 升职 / 加薪 / 职业倦怠 / 职业发展）。原因很直接：这些词会让「如何让老板给我升职加薪」这类内容挂到母问题上，而它根本不回答这个问题。两处用同一套判据，才能保证「图上显示的相关条数」和「新问题判定里说找不到相关讨论」不互相矛盾。

### 3.4 覆盖不足是产品要表达的内容

当前公开内容底账 30 条，按母问题逐条比对后**没有一条直接相关**，因此三维图上显示「公开来源 0 条」。

这不是故障，而是结论本身。页面把这句说明直接写在图上：

> 已按「在校生找第一段 AI 产品实习」逐条比对当前可检索到的公开内容（共 30 条，全部不指向在校生找第一段实习，已排除），没有一条写清一个具体的人在这一步的完整经过。这处空白是本次调查要填的部分。

三个缺口也遵循同一逻辑：**能读到的部分写清来源，读不到的部分如实留空。**

### 3.5 相反经历识别

两份经历如果在「本科 / 大厂 / 创业公司 / 有真实用户」等条件上相近、结果却相反，会被自动标记为对照连线，提示「值得继续追问」，**而不是取平均**。

## 四、三维图谱

页面主体是一张 **时间 × 子命题 × 内容数量** 的三维图：

- **横轴时间**：左半段是更早的公开来源（2020–2023），右半段是当前调查区间（2024–2027），按季度划分。
- **纵轴子命题**：六条固定子命题。
- **高度内容数量**：这一格里有几条内容。

**每颗星都是一条可以点开核对的内容**；密度微光只表示「这一格内容多」，不可点击、不计入统计。三根轴共用同一个原点，都是直线。

**粒子是细小星光点，不是泡泡或球体**——这是硬约束。

## 五、技术方案

### 5.1 架构

- **前端**：原生 HTML / CSS / JS，零构建依赖，单页八个视图。三维图谱用 Three.js 绘制，**不引任何外部 CDN**，全部资源同源加载。
- **服务端**：Node + Express，负责语料获取与缓存、身份与采访流程、追问生成、覆盖度计算、图谱数据、回答草稿生成、限流与降级。
- **数据**：JSON 文件持久化，结构简单、可审计。
- **内容接口**：知乎黑客松免鉴权公开内容接口（故事 / 知识）；知乎开放平台搜索接口（可选，凭证仅存服务端）。
- **字体**：自托管分片字体（105 个 woff2，约 6.11MB），**不依赖任何第三方字体服务**，保证首屏无外部请求。

### 5.2 问题拆解这一步，我们不冒充大模型

新问题能不能启动，用的是**可解释的规则判定**：

- **边界判定**：问题太宽（出现「所有 / 一切 / 人生 / 社会」这类词，或没有具体限定）会先要求收窄，并给出改写示例。
- **具体度判定**：需要同时出现具体人群与具体阶段，才允许启动。
- **内容充分度判定**：与当前抓取到的公开内容逐条比对，已经足够充分的问题不会被重复启动。

这样做的原因是：这一步的目标是**把问题问清楚、把未知标出来**，不是生成结论。规则化实现完全可复现、可审计、不会凭空编造地点或事实。规则表全部在开源仓库中，评委可以逐行核对。

### 5.3 大模型用在哪里

服务端已实现可选的模型接入（`/api/huowenti/llm-config`），但**默认走确定性实现**：

- 追问生成：默认由规则完成（针对刚填内容里的数字、模糊表述、缺来源的说法追问），可解释、可复现。
- 回答草稿：只由已确认的公开来源和当事人经历拼成，**不添加任何未经验证的说法**。

未配置凭证时页面如实标注是哪一种，不会假装是模型生成。

### 5.4 动效与页面设计（遵循公开的 motion-web 规范）

- **时长阶梯 6 档**：instant 90ms / fast 170ms / standard 320ms / medium 460ms / slow 700ms / cinematic 1200ms
- **真实弹簧缓动**：CSS `linear()` 描述欠阻尼弹簧（stiffness 60–90、damping 0.86–0.93），入场有轻微过冲
- **帧率无关的跟随**：视角跟随按 `1-exp(-k·dt)` 计算，不随帧率变化
- **滚轮惯性防护**：累积 90px 触发、锁定 600ms、速度按 0.92 衰减
- **静止呼吸**：不同元素用不同频率的微光，避免整页同步闪烁
- **reduced-motion 三级降级**：位移动画降为纯淡入、呼吸与微光停止、过渡全部关闭，**内容照常出现**

### 5.5 工程可信度（可复现）

| 验收 | 覆盖范围 | 本轮实测结果 |
| --- | --- | --- |
| 浏览器端到端 31 项 | 首屏 / 三维图真的画出内容 / 持续运动 / 响应式 / 设计令牌 / 采访到贡献卡全流程 / 追问 / 结论页 / 回答草稿 / 新问题判定 / 滚轮 / reduced-motion / 移动端 | **31 项通过，0 失败** |
| 版块形状多样性 | 八个版块的结构差异 | **8 个版块 / 8 种形状** |
| 字号对比度 | 最大字号与正文字号比 | **66px / 14px = 4.7 倍** |
| 响应式 | 320 / 375 / 414 / 768 / 1440 | **横向溢出均为 0** |
| 设计令牌 | 页面引用的 CSS 变量 | **引用 29 个，失效 0 个** |
| 安全边界 | 同源约束 | **外部请求 0 条，CSP 未被破坏** |

## 七、与知乎社区生态的契合

- **内容基础**：知乎沉淀了大量第一手经历（「我投了多少份」「面试被问了什么」），这是**活问题**天然的背景语料，也是别的平台不具备的资产。
- **提问机制**：知乎已经形成了成熟的「有人提问、有人回答」习惯。**活问题**把它推进到「按位置提问、可交叉比较、逐条可核对」的一步。
- **回答回流**：产品的终点是**一份可以在知乎发布的回答草稿**，用户可以修改后自行发布。这让每一次参与都能回流到知乎的内容生态。
- **补位而非替代**：**AI 负责把问题问清楚，人负责回答只有人能回答的部分。**

## 八、对社区用户的实际价值

1. **解决一类真实存在、目前无人解决的问题**：正在找第一段实习的学生，今天只能看到方法帖，看不到别人完整的失败过程。
2. **让「我经历过」第一次被结构化记录**：身份、条件、结果、卡点，全部留痕且可横向比较。
3. **不制造幻觉**：公开内容不足就显示不足，只有一份经历就说不能说明普遍情况，出现相反经历就保留矛盾。
4. **低门槛贡献**：不需要写长文、不需要露脸，回答 5 至 6 个问题即可，可选择匿名。
5. **可复现、可审计**：31 项验收全部实跑通过，规则表开源在仓库中。

## 九、诚实边界（我们明确不做的事）

- 不伪造知乎来源、匹配率或当事人经历；公开内容不足时如实显示为 0 并说明原因。
- 不把单条个人经历标成普遍事实。
- 不自动发布任何内容到知乎。
- 不编造数字，页面上每个统计值都来自当前真实数据。
- 静态资源白名单：源码、数据、脚本、日志、配置一律不通过 HTTP 提供。
- 不自动读取 GPS，不要求实名。

**下一阶段路线**：
