# 活问题｜投递版讲稿

> 本文件是给初评选拔用的自包含版本：不依赖视频也能看懂产品是什么、凭什么成立、哪里已经跑通、哪里还没做。
> 公网 Demo：**https://zaichang.cauai.fun**

## 一句话

**有些答案不在互联网上，它们还在经历过这件事的人手里。**

活问题把一个问题拆开、标出公开内容答不清楚的部分，然后主动去找真正经历过的人，把他们的经历变成可以互相比较、逐条核对的记录。

## 问题

有一类问题，搜索和生成式 AI 结构性地答不了：

> 「2027 届普通本科生找第一段 AI 产品实习到底有多难？」

公开内容里有大量方法和建议——「简历要怎么写」「面试怎么准备」「项目要有数据」。但它们有一个共同的空洞：**不包含一个具体的人从投递到被拒或被录用的完整经过**。

而且这类问题的答案散落在不同位置的人手里：

- 经历过失败的人知道卡在哪一步，但失败过程通常不会被写出来；
- 招聘一侧知道筛选的真实顺序，但几乎不会公开讲；
- 同一个项目在不同类型公司得到的反馈可能完全相反，但没人把两种结果放在一起比过。

缺的不是更多建议，而是**真正经历过的人**。这是当前 AI 能力边界之外、但知乎社区刚好能补上的一块。

## 产品解法

一个问题被拆成八个可追踪的步骤：

```text
① 活问题现场   一个问题，先展示它现在能回答到什么程度
② 三个缺口     把「读不到的部分」逐条标出来，作为去找人的理由
③ 参与采访     按位置选身份，问题只问那一部分
④ 追问         针对刚填的内容，追一个只有当事人能回答的问题
⑤ 贡献确认     生成贡献卡，用户确认后才进入调查
⑥ 问题变化     这份经历让哪一条子命题的覆盖状态变了
⑦ 当前结论     六条子命题各自的证据状态、相反经历与仍未解决
⑧ 知乎回答     整理成一份可编辑、可复制的回答草稿
```

关键设计是**按位置提问**：同一个问题，不同位置的人知道的东西不一样。招聘一侧不会被问「你投了多少份」，求职者不会被问「你们怎么筛简历」。

## 为什么可信：证据模型

这是活问题区别于普通问答产品的部分。可信度不是一个黑盒分数，而是四种可解释、可复核的状态，**按六条子命题分别计算**：

| 状态 | 含义 |
| --- | --- |
| 已有多份经历 | 可以开始比较条件差异 |
| 只有一份经历 | 还不能说明普遍情况 |
| 只有公开讨论 | 缺少当事人提供的完整过程 |
| 覆盖不足 | 当前检索范围内覆盖不足 |

判定顺序体现产品立场：**当事人的完整过程比公开讨论更有价值，但只有一份时仍然不能说普遍。**

**相关性判据只有一套**：同一个关键词表同时用于「地图上挂哪些内容」和「提出新问题时判断这个领域够不够」。只有当内容直接指向母问题（实习 / 求职 / 面试 / 简历 / 校招 / 应届 / 招聘 / 投递 / offer / 本科 / 毕业生 / 就业 / 产品经理…）才算相关；泛职场内容（升职加薪、职业倦怠、职业发展）一律排除。

**缺口是真的、可验证的**：当前 30 条公开内容按母问题逐条比对后，**没有一条直接相关**，因此三维图上显示「公开来源 0 条」。这不是页面故障，而是这个产品要表达的缺口——一个真实存在、但公开内容答不清楚的问题。产品的价值恰恰在于指出这块空白，然后去找能填上它的人。

**相反经历不取平均**：两份经历如果在条件上相近、结果却相反，会被标记为对照连线，提示继续追问。

## 三维图谱

页面主体是一张 **时间 × 子命题 × 内容数量** 的三维图：横轴是时间（左半段是更早的公开来源，右半段是当前调查区间），纵轴是六条子命题，高度是这一格里有几条内容。

**每颗星都是一条可以点开核对的内容**；密度微光只表示「这一格内容多」，不可点击、不计入统计。**粒子是细小星光点，不是泡泡或球体。**

## 与知乎生态的契合

- 知乎沉淀的大量第一手经历，是活问题天然的背景语料。
- 知乎已经养成「有人提问、有人回答」的社区习惯。活问题把它推进到**按位置提问、可交叉比较、逐条可核对**的一步。
- 产品的终点是**一份可以在知乎发布的回答草稿**，用户可以修改后自行发布——每一次参与都能回流到知乎的内容生态。
- 我们刻意不做「AI 替你回答一切」：**AI 负责把问题问清楚，人负责回答只有人能回答的部分。**

## 技术方案

- **前端**：原生 HTML / CSS / JS，零构建依赖，单页八个视图；三维图谱用 Three.js，**不引任何外部 CDN**。
- **服务端**：Node + Express，负责语料获取与缓存、身份与采访流程、追问生成、覆盖度计算、图谱数据、回答草稿生成、限流与降级。
- **拆解这一步不冒充大模型**：新问题能不能启动，用的是可解释的规则判定（边界判定 / 具体度判定 / 内容充分度判定），产出明确结论，不生成内容。
- **数据**：JSON 文件持久化，结构简单、可审计。
- **字体**：自托管分片字体（105 个 woff2，约 6.11MB），**不依赖任何第三方字体服务**，首屏无外部请求。
- **动效**：遵循公开的 motion-web 规范——6 档时长阶梯、真实弹簧缓动（CSS `linear()`）、帧率无关跟随、滚轮惯性防护、reduced-motion 三级降级。

## 诚实边界

- 不伪造知乎来源、匹配率或当事人经历；公开内容不足时如实显示为 0 并说明原因。
- 不把单条个人经历标成普遍事实。
- 不自动发布任何内容到知乎。
- 不自动读取 GPS，不要求实名。
- 未配置凭证时如实标注为关闭，不假装是实时结果。
