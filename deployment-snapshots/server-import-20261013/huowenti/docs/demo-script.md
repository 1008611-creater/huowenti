# 活问题｜3 分钟 Demo 脚本

> 目标：让评委在 3 分钟内看懂「一个问题 → 它读不到的部分 → 去找真正经历过的人 → 经历变成可比较的记录 → 结论随证据变化」的完整闭环。
>
> 演示前确认：公网地址 **https://zaichang.cauai.fun** 能打开，首页就是母问题「2027 届普通本科生找第一段 AI 产品实习到底有多难？」。服务部署在服务器上，容器开机自启、异常自动重启，本机不需要开着。

---

## 0:00–0:15 抛出问题

**（首页 · 活问题现场）**

> 「2027 届普通本科生找第一段 AI 产品实习到底有多难？」

这类问题有一个共同点：**公开内容里全是方法和建议，却没有一个具体的人从投递到被拒或被录用的完整经过。**

搜索能给出「简历要怎么写」，AI 能总结「面试怎么准备」——但没人能说清，**一个普通本科生在这一次投递里，到底卡在哪一步。**

## 0:15–0:45 先说清「它不知道什么」

**（向下滚动到「三个缺口」）**

页面上三条缺口不是写出来的文案，而是**实际检索之后留下的空位**：

- 普通本科、没有互联网实习者的**完整失败过程**；
- 招聘参与者对**简历淘汰和面试判断**的具体说明；
- 同一种项目经历在**不同公司类型**中的实际结果差异。

> 注意这一步：**它不会假装自己知道。** 能读到的部分写清来源，读不到的部分如实留空。
>
> 如果评委问「你们用了什么模型」——如实回答：判断一个内容算不算相关、一个缺口有多大，用的是可解释的规则判定，可逐行核对，不生成内容。

## 0:45–1:15 内容分布：三维图谱

**（滚到「时间 × 子命题 × 内容数量」）**

页面主体是一张三维图：横轴是时间，纵轴是六条子命题，高度是这一格里有几条内容。

**（拖动旋转一次，再点一颗星）**

**每颗星都是一条可以点开核对的内容**；密度微光只表示「这一格内容多」，不可点击、不计入统计。

> 这里要主动说一句实话：当前 30 条公开内容按母问题逐条比对后，**没有一条直接指向「在校生找第一段 AI 产品实习」**，所以图上公开来源显示为 **0 条**。
>
> 这不是页面故障——**这正是这个产品要表达的缺口。** 一个真实存在、但公开内容答不清楚的问题。产品的价值恰恰在于指出这块空白，然后去找能填上它的人。

## 1:15–2:00 参与采访：按位置提问

**（点「回答一个只有你知道的问题」）**

四类身份：**我已经拿到实习或进入面试 / 我投递过但没有结果 / 我正在找第一段 AI 产品实习 / 我参与过招聘或面试。**

> 关键设计是**按位置提问**：同一个问题，不同位置的人知道的东西不一样。招聘一侧不会被问「你投了多少份」，求职者不会被问「你们怎么筛简历」。

**（选「我投递过，但没有结果」，填 6 个问题）**

问题只问这一部分：投递渠道、投递数量、简历反馈、面试阶段、具体淘汰位置、最终结果。

## 2:00–2:30 追问与贡献确认

**（提交后出现追问框）**

系统会**针对刚填的内容**追一句，而不是固定话术。例如填了「投了 60 份」，它会问：

> 「你提到的这个数字，是从哪里得到的？」

> 这一步是整个产品的关键——**追问必须基于当事人刚说的话**，否则拿到的还是一条无法比较的经历。

**（生成贡献卡）**

贡献卡把这段经历拆成若干条事实。注意：**确认之后它才会进入调查**，而且用户可以随时删除。

## 2:30–3:00 问题变化、结论与知乎回答

**（进入「问题变化」）**

这一步回答的是：**这份经历让哪一条子命题的覆盖状态变了。** 变化为 0 的地方如实写 0，说明这段经历没有触及那一条。

**（进入「当前调查结论」）**

六条子命题各自的证据状态、相反经历与仍未解决的部分，一目了然。可信度不是一个黑盒分数，而是四种可解释的状态：**已有多份经历 / 只有一份经历 / 只有公开讨论 / 覆盖不足**。

> 判定顺序体现产品立场：**当事人的完整过程比公开讨论更有价值，但只有一份时仍然不能说普遍。**

**（进入「知乎回答」）**

最后，把当前调查整理成一份**可编辑、可复制**的回答草稿。它不是自动发布的内容——用户可以修改后自行发布。

**（收尾）**

> 当 AI 已经读过互联网，知乎可以让它继续向现实中的人发问。
>
> 活问题做的事情很简单：**把一个问题读不到的部分标出来，然后去找那些真正经历过的人。**

## 现场问答准备（2 分钟）

**Q：这不就是发问卷吗？**
不是。问卷是「我设计好选项，你来选」；活问题是「问题先自己承认读不到什么，再按你的位置问你那一部分，然后追一句只有你能回答的」。而且每份经历进入调查后会**改变覆盖状态**，不同人的经历会被放在一起比较——问卷不产生这种结构。

**Q：为什么可信？**
四件事：一是**判据只有一套**，同一套关键词同时用于「地图上挂哪些内容」和「判断新问题够不够」，不存在两套口径；二是**证据状态可解释**，不是分数；三是**相反经历不取平均**，条件相近、结果相反会被标记为对照连线；四是**没有内容就说没有**，公开来源 0 条就显示 0 条。

**Q：知乎 API 挂了怎么办？**
降级路径是设计好的。没有凭证时产品依然完整可用：公开内容为空就如实显示为空，实时能力标注为关闭。**不伪造来源是产品底线。**

**Q：这跟普通问答社区有什么区别？**
普通社区是「广播」——碰巧有人看到才有答案。活问题是**定向、结构化的发问**：按位置提问、按子命题归集、逐条可核对、覆盖状态随参与变化。它不是更热闹的问答，是**证据积累机制**。

**Q：为什么用户愿意回答？**
因为请求足够具体。他不需要理解你的完整处境，只需要回答他确实知道的那一部分。而且终点是一份**可以发到知乎的回答草稿**，参与本身就有回报。

**Q：怎么防止滥用和数据泄露？**
不自动读取 GPS，不要求实名，不收集与问题无关的信息；贡献可以随时删除；服务端只对外提供前端必需文件，源码、数据、脚本一律不通过网页暴露；页面不加载任何第三方脚本或统计代码，因此**不产生任何外部请求**。

**Q：技术上最难的是什么？**
不是接口，是**判断的克制**。我们花了大量精力处理「什么算相关」「什么时候不该下结论」——泛职场内容（升职加薪、职业倦怠、职业发展）不回答「在校生找第一段实习」这个问题，一律排除；只有一份经历时不能说普遍。这些都已经固化成验收项，保证不会退步。

**Q：评委现在能自己试吗？**
能。直接打开 https://zaichang.cauai.fun ，不需要注册，不需要配置任何东西，全流程可跑。
