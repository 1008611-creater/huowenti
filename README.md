# 活问题 · Living Question

> 一个会主动寻找回答者的问题。

知乎黑客松 2026 参赛作品。公开内容能回答的部分照实引用；回答不了的部分不被编造，而是变成一条**会主动去找人**的问题：找到真正经历过这件事的人，收集可追溯的真实过程，再形成分维度的结论。

当前的问题：**2027 届普通本科生找第一段 AI 产品实习到底有多难？**

---

## 它要解决什么

有一类问题，搜索引擎和生成式 AI 结构性地答不了：

- 「普通本科、没有大厂实习的人，第一段 AI 产品实习到底卡在哪一步？」
- 「面试官到底看项目功能，还是看用户数据和个人贡献？」
- 「同一个项目，投大厂和投 AI 创业公司，结果为什么不一样？」

它们的共同点是：**答案不在公开内容里，而在具体某个人的经历里。** 公开内容给出的是方法和观点，读不到一个具体的人从投递到被拒的完整过程；招聘一侧的判断依据更是几乎没有。现有社区提问也不行，它依赖「碰巧有当事人看到」，没有定向触达。

所以这里没有让 AI 去猜，而是把「谁真的经历过」变成一条可以主动触达、可以交叉验证的链路。

## 产品闭环

    ① 提出活问题    公开内容覆盖不足的地方被显式标出来
    ② 找到当事人    按四类参与身份定向找人，而不是等人路过
    ③ 采访与追问    只问这一步真正缺失的事实，可随时退出、可匿名
    ④ 确认贡献      当事人确认后才进入调查，不自动发布
    ⑤ 记录变化      每份经历进入前后，覆盖情况的变化被记录下来
    ⑥ 分维度结论    哪些可以相信、哪些只有单一来源、哪些存在冲突
    ⑦ 知乎回答草稿  只用已有内容和当事人提交的经历，不补充未提供的事实

## 页面结构

首页是「活问题现场」，共六个视图：

- **活问题现场**：问题边界、公开内容已经说了什么、仍然读不到的部分、三个缺口，以及一张三维内容分布图（时间 × 子命题 × 内容数量）。每颗星是一条可以点开核对的内容，微光只表示密度、不可点击。
- **参与采访**：四类参与身份 —— 已经拿到实习或进入面试、被拒过、正在找第一段实习、招聘一侧的参与者。每类身份只问与他相关的那几步。
- **当前结论**：按六条子命题（初始背景、项目经历、投递过程、面试筛选、公司差异、最终结果）给出证据状态与还缺什么，并列出「条件相近但结果相反」的对照。
- **知乎回答**：把公开内容和当事人经历整理成回答草稿。
- **知识宇宙**：内容与贡献之间的关系图。
- **提出新问题**：判断一个新问题是否适合作为活问题。

## 数据从哪来

- 公开内容来自知乎开放接口，真实抓取后存在 data/corpus.json：故事 20 条、知识 10 条，每条都带原始链接和标题。
- 接口本身不返回发布时间，代码按知乎内容 ID 的位规则推算创建时间，页面上如实标注为「按内容 ID 推算」，不把它当成接口给出的时间。
- 参与者的经历只写在本机 data/huowenti.json，不经过任何第三方。

## 如实说明的边界

这一节写的是当前真实状态，不是宣传话术：

- data/huowenti.json 目前是空的（还没有真实参与者提交过经历）。因此「当前结论」页面现在展示的是公开内容的覆盖情况，不包含任何当事人经历。
- 采访流程里有一段写死的示例身份，代码里标注为「演示身份」，用于演示完整流程，它不是真实用户。
- 语言模型是可选配置。未配置时，追问和整理由本地规则生成，同样只使用用户提供的信息，不会补充未提供的事实。
- 知乎开放接口需要密钥。未配置时相关功能降级，页面如实显示空状态，不编造数据。

## 技术栈与目录

Node.js + Express，前端是原生 HTML / CSS / JavaScript，数据用 JSON 文件持久化。三维图谱用本地自带的 three.js，字体全部自托管，前端不依赖任何外部 CDN，可以完全离线演示。

    huowenti.html / huowenti.css / huowenti.js   活问题前端（默认首页）
    server.js                                    服务端入口，同时提供接口与静态资源
    lib/huowenti.js                              活问题的核心逻辑：身份、采访、贡献、结论
    lib/corpus.js                                知乎公开内容的抓取与缓存
    lib/matcher.js / lib/evidence.js             问题拆解与证据判定
    lib/weather.js                               现场天气（作为背景信息，不作为结论）
    data/corpus.json                             真实抓取到的知乎公开内容
    data/huowenti.json                           参与者提交的经历（当前为空）
    assets/fonts/                                自托管字体
    assets/vendor/                               three.js、二维码生成器（均为本地副本）
    scripts/                                     回归测试、边界检查、冒烟测试

本仓库同时包含同源的「在场 / Zaichang」页面（index.html、app.js、case.html、verify.html 等）。它和活问题共用同一个 server.js，活问题是默认首页。

## 本地运行

需要先装好 Node.js，然后在项目目录里依次执行：

    npm install
    npm start

然后打开 http://localhost:4173/ 。换端口用环境变量 PORT。

## 自检

    npm run check        证据判定回归 + 浏览器端验收 + 静态资源边界检查
    npm run smoke        后端接口端到端（需要服务已在运行）

scripts/security-check.mjs 会逐项确认：后端源码、数据文件、脚本、日志都不通过 HTTP 对外提供，目录穿越被拦截，安全响应头到位。这是「现场演示 + 公网部署」都要守住的红线。

## 隐私与安全

- 参与者的经历只落盘在本机 data/huowenti.json，仓库里该文件是空状态。
- 仓库中不含任何密钥。需要密钥的能力通过环境变量配置，示例见 .env.example（值全部为空）。
- data/cases.json（在场的使用数据）与 logs/ 已在 .gitignore 中排除，不会进入仓库。
